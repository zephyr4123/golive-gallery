# 部署教程总纲

> 把一个网站放到公网上,让别人能打开。这份文档从"这些名词是什么意思"一路讲到"原子回滚怎么做"。

## 三层结构

文档分三层,各管一件事——**看不懂的时候往上一层查,想动手的时候往下一层走**:

| 层 | 回答什么 | 目录 |
|---|---|---|
| **基础** | 这个词是什么意思、它凭什么能工作 | [`basics/`](basics/) |
| **教程** | 在具体平台上,一步一步该敲什么 | [`guide/`](guide/) |
| **实战** | 本项目这三个站,各自是怎么造出来的、踩了什么 | [`sites/`](sites/) |

## 我该从哪开始

### 完全没接触过代码 / 服务器 / 域名

先去 [`basics/`](basics/README.md)。八篇,从"网页是怎么送到人眼前的"讲到"内网穿透的原理",大约一小时读完。**不用全读**,那里的导读会告诉你按你要走的路线该挑哪几篇。

### 会写点前端,只是没上过线

直接从下面的教程表挑一档。名词卡住了随时回 [`basics/`](basics/README.md) 查——每一档的正文都会在需要的地方给出链接。

## 两条写作纪律

**一、只有做完了才写。** 没在真机上跑通的步骤,一个字都不写——宁可显式声明「未做」并列出待验证项。没跑过就写出来的步骤,读者照着走一定会在某个没预料到的地方卡住,而作者不知道卡在哪,那比没有文档更糟。所以各篇进度是分开的,标「待写」的就是还没做。

查证过出处的平台事实(官方定价、配额、协议行为)可以先写,但要与"跑通过的步骤"分层标注,并写明核实日期——**这类政策一年一变,照抄两年前的中文教程大概率是错的**。

**二、正文永远教手动步骤。** `golive` CLI 只出现在每章末尾的"学会原理后,一条命令搞定"栏目,其 `--dry-run` 输出与正文命令保持一致。工具是用来省事的,不是用来替你理解的。
