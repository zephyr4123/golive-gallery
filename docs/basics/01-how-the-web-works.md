# 01 · 网页是怎么送到人眼前的

> 你在地址栏敲一个网址、按回车,一两秒后页面出来了。这一两秒里发生了五件事。
> 把这五件事拆开,后面所有教程里的名词就都有位置可放了。

## 先纠正一个最常见的误解

「把网站放到网上」听起来像是把文件传到某个叫"网上"的地方。

其实不是。**互联网上没有"网上"这个地方,只有一台一台的电脑。** 所谓上线,是让**某一台一直开着机、有固定地址的电脑**,在别人来问的时候,把你的文件递出去。

那台电脑可以是:

- 别人的(GitHub、Cloudflare 的机房)——这是[免费托管档](../guide/01-free-hosting/README.md)
- 你租的(云服务器)——这是[工业级档](../guide/03-vps/README.md)
- **你自己这台**(通过一条隧道让公网找得到它)——这是[内网穿透档](../guide/02-tunneling/README.md)

三档教程的区别,从头到尾就只是"递文件的是哪台电脑"。

## 那一两秒里的五件事

以访客打开 `https://denta.<你的域名>/` 为例。

### 一、把网址拆开

浏览器先把这串字符拆成几部分:

```
https://denta.<你的域名>/about?from=wechat
└─┬─┘   └────────┬───────┘└─┬──┘└────┬────┘
 协议          主机名        路径     查询参数
```

- **协议** `https` —— 用什么规矩说话(`http` 是明文,`https` 是加密的,见 [06 篇](06-https-and-certificates.md))
- **主机名** `denta.<你的域名>` —— 去找谁。**这是一个名字,不是地址**
- **路径** `/about` —— 要那台机器上的哪个东西
- **查询参数** `?from=wechat` —— 附带的说明,交给对方自己解释

真正决定"流量去哪台机器"的,只有主机名这一段。路径和参数是到了之后才起作用的。

### 二、把名字换成地址

电脑之间通信认的是 **IP 地址**(像 `172.67.184.251` 这样一串数字),不认名字。所以浏览器要先问:`denta.<你的域名>` 对应哪个 IP?

回答这个问题的系统叫 **DNS**,细节在 [05 篇](05-domain-and-dns.md)。你可以自己跑一次:

```bash
dig +short denta.<你的域名>
```

拿到的就是一串 IP。**这一步失败,后面全都不会发生**——浏览器会告诉你"找不到服务器",而不是"网站打不开"。这两句报错含义完全不同,分清楚能省掉大量瞎猜。

### 三、连上去,并且验明正身

拿到 IP 之后建立连接。如果协议是 `https`,连上之后还要多做一步:对方得出示一张**证书**,证明"我确实是 `denta.<你的域名>` 这个名字的合法持有者"。

浏览器验完证书才继续,验不过就直接拦下来,给你那个红色的警告页。这也是为什么地址栏有把小锁——锁的意思不是"这个网站是好网站",而是"你连上的确实是这个域名,且中间传的内容别人看不到"。详见 [06 篇](06-https-and-certificates.md)。

### 四、开口要东西

连接建好了,浏览器发出一段请求,核心就三行:

```
GET /about HTTP/2
Host: denta.<你的域名>
User-Agent: Mozilla/5.0 ...
```

`Host` 这一行值得单独记住:**它告诉对方"我要的是哪个网站"**。

为什么需要它?因为一台服务器上通常挂着成百上千个网站,它们共用同一个 IP。DNS 只把你送到门口,进门之后靠 `Host` 分辨你找谁。

这解释了一个很多人第一次绑域名时想不通的事:GitHub Pages 上所有人的站,CNAME 都填同一个值,凭什么不打架?——就凭这一行。也解释了[内网穿透档](../guide/02-tunneling/README.md)里那个 403:本地的 `vite preview` 看到一个陌生的 `Host` 就拒绝服务了。

对方回一段响应:

```
HTTP/2 200
content-type: text/html

<!doctype html><html>...
```

第一行的 `200` 是**状态码**,浏览器和你都靠它判断发生了什么。常见的几个:

| 状态码 | 意思 | 典型原因 |
|---|---|---|
| `200` | 给你了 | 正常 |
| `301` / `302` | 不在这儿,去那边 | 网址跳转 |
| `403` | 我认识这个路径,但不给你 | 权限、或者服务端不认你的 `Host` |
| `404` | 没这个东西 | 路径写错、文件没传上去 |
| `5xx` | 我这边出问题了 | 服务端挂了、或者它后面的一环挂了 |

这五个数字在排查时比任何猜测都值钱。**先看状态码是哪一层发的**,是这个项目反复强调的排查纪律。

### 五、浏览器把文件拼成页面

拿到的第一份文件是 **HTML**——页面的骨架,纯文本。浏览器一边读一边发现里面还引用了别的文件:

```html
<link rel="stylesheet" href="/assets/index-wqoXrgw6.css">
<script src="/assets/index-5TJ8J1MI.js"></script>
```

于是它再跑一遍第二到第四步,把这些文件也要回来:

- **CSS** —— 长什么样(颜色、字号、排版)
- **JavaScript** —— 会做什么(点击、动画、动态加载)
- 还有图片、字体等等

全部到齐、拼装完毕,你才看见那个页面。**所以一个网页从来不是一个文件**,而是一堆文件。这也是为什么本项目每次验证站点上线,不光看首页返回 200,还要逐个检查 JS 和 CSS 是不是也都 200——首页通了但资源 404,你看到的会是一个白板。

## 静态站和动态站

上面第五步里,服务器做的事情只是"把现成的文件递出来",这叫**静态站**。

另一种是服务器现场算一份出来给你——比如你打开淘宝,页面里的商品是它查了数据库临时拼的,这叫**动态站**。

| | 静态站 | 动态站 |
|---|---|---|
| 服务器干什么 | 找到文件、递出去 | 跑程序、查数据库、生成内容 |
| 需要什么 | 能放文件、能响应请求就行 | 一个能长期跑程序的环境 + 数据库 |
| 上线难度 | 低 | 高 |
| 能不能白嫖托管 | 能,而且到处都是 | 基本不能 |

**本项目全部三个示范站都是静态站。** 这不是偷懒——它是"把网站放到公网上"这件事的最小完整形态:域名、DNS、证书、部署、回滚,一样不少,但不用先学数据库和服务端。等这五件事你都熟了,再加动态部分只是多一层。

顺带解释一个容易混的说法:本项目的站是用 React 写的,页面上有动画、有交互,看起来很"动态"。但那些都是**在访客的浏览器里**跑的 JavaScript 干的,服务器仍然只是递了一堆固定文件。判断静态还是动态,看的是**服务器有没有现场算**,不是页面动不动。

## 自己看一遍全过程

`curl` 这个命令行工具可以把上面的第二到第四步一次性打印出来:

```bash
curl -v https://denta.<你的域名>/ 2>&1 | head -30
```

输出里能对上号的几行:

```
* Connected to denta.<你的域名> (172.67.184.251) port 443   ← 第二、三步:名字换成了 IP,连上了
* SSL certificate verify ok.                                 ← 第三步:证书验过了
> GET / HTTP/2                                               ← 第四步:开口要
> Host: denta.<你的域名>                                      ← 就是这一行决定给你哪个站
< HTTP/2 200                                                 ← 对方回了 200
< content-type: text/html
```

`>` 开头是你发出去的,`<` 开头是对方回来的。**排查任何"打不开"的问题,第一件事就是跑这条命令**,它会告诉你断在哪一步——是名字没换成 IP、还是连不上、还是证书不过、还是对方回了个 404。
