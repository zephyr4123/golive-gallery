# 06 · HTTPS 与证书

> 地址栏那把小锁,大部分人只知道"有锁是安全的"。
> 这一篇讲清楚它到底证明了什么、那张证书是谁发的、为什么现在免费、以及证书出问题时长什么样。

## HTTPS 比 HTTP 多做了两件事

`http` 是明文。你和网站之间传的每个字节,链路上任何一环都能看见、也能改——你家路由器、运营商、公共 Wi-Fi 的提供者。

`https` 在同样的 HTTP 之外加了一层 **TLS**,它同时解决两个问题:

| | 解决什么 | 没有它会怎样 |
|---|---|---|
| **加密** | 中间人看不懂内容 | 你填的密码、看的页面,全程裸奔 |
| **身份验证** | 确认对方真是这个域名 | 有人冒充,你根本不知道 |

大部分人只想到加密,其实**身份验证才是证书存在的理由**。光加密不验身份的话,你可能在和一个冒牌网站进行一场加密良好的对话。

⚠️ 所以那把锁的含义是:**「你连上的确实是这个域名,且传输内容别人看不到」**。它**不代表**这个网站是好网站——钓鱼网站也能申请到合法证书,而且几乎都申请了。

## 证书是什么

一张证书本质上是一份**由第三方签名的声明**,核心就几项:

- **签给哪个域名**(可以是一个,也可以是一批,还可以是 `*.example.com` 这样的泛域名)
- **公钥**(用来建立加密通道)
- **有效期**
- **谁签发的**,以及那家机构的数字签名

签发方叫 **CA**(Certificate Authority,证书颁发机构)。你的操作系统和浏览器里预装了一份**受信任 CA 名单**,证书链能追溯到名单里的某一家,浏览器才认。

自己看一张真证书:

```bash
echo | openssl s_client -connect <你的域名>:443 -servername <你的域名> 2>&1 \
  | grep -E 'subject=|issuer=|Verify return code'
```

- `subject=` 签给谁
- `issuer=` 谁签的
- `Verify return code: 0 (ok)` 验证通过

## 关键:证书跟着域名走,不跟服务器走

证书里写的是**域名**,和它跑在哪台机器上完全无关。由此推出三件反直觉但很重要的事:

**一台服务器可以挂无数张证书。** TLS 握手时浏览器会先报出自己要访问的域名,服务器再按名递上对应的证书。这个机制叫 **SNI**(Server Name Indication)。所以共享 IP 的虚拟主机上,一千个网站各有各的证书,互不干扰。

**一张证书可以部署在全球无数节点。** 这是 CDN 的日常——Cloudflare 在几百个城市的机房里都拿着你域名的证书,谁离访客近谁来握手。

**换服务器不用换证书,换域名才要。**

## 为什么现在免费

2015 年之前证书要花钱买,几百到几千块一年。**Let's Encrypt** 出现之后彻底变了:它是一家非营利 CA,证书免费、全自动签发,而且被所有主流浏览器信任。

代价是有效期只有 **90 天**——短到你必须自动化续期,而这正是设计意图:强迫大家搭自动化,而不是每年手动折腾一次然后忘记。

对新手来说更重要的是:**你多半根本不用碰这些。**

| 你走哪条路 | 证书谁管 |
|---|---|
| GitHub Pages / Cloudflare Pages | 平台全自动:申请、部署、续期,零操作 |
| Cloudflare 代理(橙云) | Cloudflare 在边缘自动签发续期 |
| 自己的服务器 + Caddy | Caddy 自动向 Let's Encrypt 申请与续期 |
| 隧道服务商自家域名 | 服务商自带 |
| **隧道 + 你自己的域名** | ⚠️ **可能要你自己提供**,见下文 |

## 一个真实的例外:cpolar 不给你的域名签证书

本项目 2026-08-23 实测的一条,值得单独讲——因为它是"证书不会自动到位"的典型长相。

用 cpolar 把自定义域名接上隧道,**如果不主动给它证书**,那个域名的 443 端口是这样的:

```
$ echo | openssl s_client -connect <边缘IP>:443 -servername denta.<你的域名>
CONNECTED(00000003)
no peer certificate available          ← TCP 连上了,但对方一张证书都没出
```

TCP 连得上,TLS 握手一开始就断。**等于 HTTPS 完全不通**,而不是"证书有点问题"。

给它一张证书(`-crt` / `-key` 两个参数)之后,同一个端口立刻变成:

```
subject=CN=denta.<你的域名>            ← 出证书了
```

**教训不是"cpolar 有问题",而是:「绑了域名就自动有 HTTPS」这个默认预期,只在托管平台上成立。** 自己接线路的时候,证书是一件要单独安排的事。

## 三种证书,别用错场合

| | 谁签的 | 浏览器认吗 | 用在哪 |
|---|---|---|---|
| **公信证书**(Let's Encrypt 等) | 受信任的 CA | ✅ 认 | 访客直接访问的任何地方 |
| **自签名证书** | 你自己 | ❌ 不认,红色警告 | 内网自用,或**前面挡着一层代理**的源站 |
| **Cloudflare Origin CA** | Cloudflare | ❌ 浏览器不认,但 **Cloudflare 认** | 只用于 Cloudflare 到你源站那一段 |

生成一张自签名证书就一条命令,几秒钟:

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout my.key -out my.crt \
  -subj "/CN=你的域名" -addext "subjectAltName=DNS:你的域名"
```

**它凭什么能用在生产链路里?** 因为访客根本不直接和它握手。本项目 Denta 站现在的形态就是这样:

```
访客 ──HTTPS──> Cloudflare 边缘 ──HTTPS──> cpolar 节点 ──隧道──> 你的电脑
       ↑ 公信证书,          ↑ 自签名证书,访客永远看不到,
         Cloudflare 自动管     只需要 Cloudflare 那一端接受它
```

访客校验的是 Cloudflare 出的那张公信证书;自签名那张只服务于中间那一跳,而 Cloudflare 在 Full 模式下**不校验源站证书**,所以自签名足够。

⚠️ 这个前提要记牢:**自签名能用,是因为前面挡着一层代理、且那层代理被配置成不校验源站。** 换成访客直连,或者代理改成严格校验模式,立刻就挂。什么模式校验、什么模式不校验,见 [07 篇](07-cloudflare.md)。

🔴 **私钥(`.key` 文件)绝不能提交进版本库,也不能发给任何人。** 证书(`.crt`)是公开的无所谓,私钥泄露等于证书作废。本项目把它放在 `~/.cpolar/certs/` 下,目录权限 700、私钥 600,仓库里一个字节都没有。

## 证书出问题时长什么样

| 浏览器/命令行提示 | 什么意思 | 通常怎么回事 |
|---|---|---|
| `NET::ERR_CERT_COMMON_NAME_INVALID` | 证书签的不是这个域名 | 域名指到了别人的服务器,或者证书没覆盖这个子域 |
| `NET::ERR_CERT_AUTHORITY_INVALID` | 签发方不在信任名单里 | 用了自签名证书,而访客在直连 |
| `NET::ERR_CERT_DATE_INVALID` | 过期了 | 自动续期挂了;或者**你电脑的系统时间不对** |
| `no peer certificate available` | 对方根本没出证书 | 那个端口压根没配 TLS(上文 cpolar 那种) |
| Cloudflare `525` / `526` | CF 连源站时 TLS 失败 | 源站证书有问题,或者源站根本不做 TLS |

最后一格值得展开:**`525` 和 `526` 是 Cloudflare 特有的错误码**,意思是"访客到我这没问题,我到你的源站出问题了"。看到它就直接去查源站的证书,别再怀疑 DNS。

## 一条容易被忽略的:证书是公开可查的

所有公信证书都会被记入 **Certificate Transparency** 公开日志。也就是说,你给 `secret-project.example.com` 申请了证书,这个子域名**立刻就是公开信息**,任何人都能在 [crt.sh](https://crt.sh) 上搜出来。

别指望用"没人猜得到的子域名"来藏东西。要保护就用真正的访问控制。
