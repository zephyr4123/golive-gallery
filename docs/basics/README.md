# 基础:那些名词到底是什么

> 这一层不教任何操作步骤,只回答「这个词是什么意思、它凭什么能工作」。
> 操作在 [`../guide/`](../guide/),本项目三个站的实战记录在 [`../sites/`](../sites/)。

如果你从来没接触过代码、服务器、域名,那么打开任何一篇部署教程都会立刻撞上一堵名词墙:npm、构建、仓库、DNS、CNAME、证书、边缘节点……教程默认你懂,可没人告诉过你。

这一层就是那堵墙的说明书。**它是拿来随时回查的,不是必须从头读到尾的。**

## 只想赶紧把站放上去,读哪几篇?

不用八篇都读。按你要走的路线挑:

- **想用 GitHub Pages / Cloudflare Pages 白嫖托管** → 03、04、05、06。这条路你不需要懂隧道
- **只想让朋友现在打开看一眼,不想注册一堆账号** → 02、03、08。域名和证书那两篇可以先跳过,隧道服务商会替你搞定
- **完全零基础,想搞明白到底在发生什么** → 从 01 顺着读下去,八篇大约一小时

## 这一层的写作规矩

本项目的总规矩是[只有真跑通了才写](../guide/02-tunneling/README.md)——没做过的步骤一个字都不写。

概念层稍有不同,但界线划得很清楚:

- **通用原理与查证过出处的平台事实**(官方定价、配额、协议行为)可以写,写的时候标注核实日期
- **本项目实测出来的数字和现象**会明确标「实测」,并写清是什么时候、在什么环境上测的
- **任何具体操作步骤都不在这一层**——想知道"那我该敲什么",去 [`../guide/`](../guide/)。这一层只负责让你看懂那些步骤在干嘛
