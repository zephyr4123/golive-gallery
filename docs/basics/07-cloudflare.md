# 07 · Cloudflare 是什么

> 三档教程里它无处不在:解析在它那、证书是它签的、站托管在它上面、隧道也是它的。
> 很多人被这一堆东西搞晕,是因为**它同时在扮演四个不同的角色**。拆开看就清楚了。
>
> 平台事实核于 2026-08-23。免费档政策一年一变,照抄旧教程大概率是错的。

## 一句话:它是坐在访客和你的网站中间的那一层

传统模式下,访客直接连到你的服务器:

```
访客 ─────────────────────────> 你的服务器
```

用了 Cloudflare 之后,访客先到离他最近的 Cloudflare 机房(叫**边缘节点**),由 Cloudflare 决定接下来干什么:

```
访客 ──> Cloudflare 边缘节点 ──> 你的服务器(叫"源站",origin)
              │
              ├─ 有缓存?直接给,根本不打扰源站
              ├─ 是攻击流量?拦掉
              └─ 顺便把 HTTPS 也办了
```

**「源站」这个词记一下**,后面所有文档都在用:它指的是你真正放着网站的那台机器——可能是 GitHub 的服务器,也可能是你自己的笔记本。

## 四个角色

### 一、DNS 解析商

回答"这个域名指向哪"([05 篇](05-domain-and-dns.md)的模型一)。这是**唯一一个必须用的角色**——把域名的 NS 记录改到 Cloudflare,其它功能才谈得上。

它的解析速度常年排全球前列,而且免费不限量。哪怕你什么别的功能都不用,只拿它当解析商也划算。

### 二、CDN(内容分发网络)

把你的静态文件复制到全球几百个机房。访客从最近的那个拿,而不是绕半个地球回你的源站。

对静态站来说这几乎是白送的加速——**而且能挡住绝大部分流量根本不打到源站上**。这一点对[内网穿透档](../guide/02-tunneling/README.md)尤其有意义:源站是你自己的笔记本,能少打扰就少打扰。

### 三、反向代理与安全网关

因为流量都从它那过,它顺手就把这些做了:DDoS 防护、机器人识别、防火墙规则、限速。

**副作用是:你的源站真实 IP 被藏起来了。** 外面 `dig` 你的域名,拿到的是 Cloudflare 的 IP,不是你的。这既是安全收益,也是排查时的困惑来源——查出来的 IP 不是你的机器,不代表配错了。

### 四、托管与隧道服务商

- **Cloudflare Pages** —— 直接托管静态站,连着你的 Git 仓库自动构建部署([01 档](../guide/01-free-hosting/README.md))
- **Cloudflare Tunnel** —— 从你自己的机器打一条长连接出来,让公网能访问它([02 档](../guide/02-tunneling/README.md))

## 橙云和灰云:这一栏决定一切

在 Cloudflare 的 DNS 记录列表里,每条记录都有一个 **Proxy status**(代理状态)开关,显示成一朵云:

| | **Proxied(橙云 🟠)** | **DNS only(灰云 ☁️)** |
|---|---|---|
| 流量走哪 | 访客 → CF 边缘 → 你的源站 | 访客 **直连** 你的源站 |
| `dig` 查出来的 IP | Cloudflare 的 | 你源站真实的 |
| CDN 缓存 / 防护 | ✅ 生效 | ❌ 全都不生效 |
| HTTPS 证书 | Cloudflare 在边缘替你办 | ⚠️ **你的源站得自己有证书** |
| 源站 IP 是否暴露 | 藏着 | 暴露 |

**上面那一堆功能,只在橙云打开时才存在。** 灰云时 Cloudflare 就只是一个普通的解析商,别的什么都不做。

新手常见的困惑是"我用了 Cloudflare 为什么没加速"——多半就是这一栏是灰的。

本项目三个站的记录**全部是橙云**。

## SSL/TLS 加密模式:最容易踩坑的一项

橙云打开后,链路被切成两段,**两段的加密是分别配置的**:

```
访客 ──第一段──> Cloudflare 边缘 ──第二段──> 你的源站
      永远是 HTTPS                这一段由"加密模式"决定
```

模式在面板的 **SSL/TLS → Overview** 里选。Cloudflare 官方的五种(核于 2026-08-23):

| 模式 | CF 到源站走什么 | 校验源站证书吗 | 什么时候用 |
|---|---|---|---|
| **Off** | HTTP | — | 基本别用 |
| **Flexible** | **HTTP** | 不校验 | 源站完全不支持 HTTPS 时的下策 |
| **Full** | HTTPS | **不校验** | 源站有证书但是自签名/不合规 |
| **Full (strict)** | HTTPS | ✅ 校验 | 源站有合规证书,最推荐 |
| **Strict (SSL-Only Origin Pull)** | HTTPS | ✅ 校验 | 企业档 |

三件必须知道的:

**🔴 这个设置是 zone 级的,一改影响整个域名下所有站。** 本项目域名下挂着三个站,分别托管在 GitHub Pages、Cloudflare Pages 和一条 cpolar 隧道上——改这一项要三个一起回归。**动它之前先想清楚都会波及谁。**

**⚠️ Flexible 很容易造成无限重定向。** CF 用 HTTP 回源 → 源站自动把 HTTP 跳转到 HTTPS → CF 把跳转回给访客 → 访客再来 → 又用 HTTP 回源……浏览器报 `ERR_TOO_MANY_REDIRECTS`。所以本项目的 GitHub Pages 站必须**关掉** GitHub 那边的 Enforce HTTPS。

**✅ Full 接受自签名证书,这是它的正经用法。** 官方文档原话是这个模式 "is common for origins that use self-signed or otherwise invalid certificates"。本项目的 Denta 站正是靠这一点:源站(cpolar 节点)拿的是一张自签名证书,zone 停在 Full 就通,**完全不用改 zone、不波及另外两个站**(实测,2026-08-23)。

## Universal SSL:免费证书覆盖到哪

橙云打开后,Cloudflare 自动给你的域名签发证书,免费、自动续期、零操作。

⚠️ **但它只覆盖根域和一级子域**:

| 域名 | 覆盖吗 |
|---|---|
| `example.com` | ✅ |
| `denta.example.com` | ✅ 一级子域 |
| `a.b.example.com` | ❌ **二级子域不覆盖** |

要覆盖更深的层级得单独买 Advanced Certificate Manager。规划子域名结构时**尽量保持一级**,能省掉这笔钱和这个坑。

## 免费档给什么

不需要信用卡:

- DNS 解析,不限记录数、不限查询量
- CDN 与 DDoS 防护,**不限带宽**
- Universal SSL 证书
- Cloudflare Pages:每月 500 次构建,**每个项目最多 100 个自定义域**
- Cloudflare Tunnel:免费
- 10 条 Configuration Rules(可以按主机名单独覆盖某些设置,包括加密模式)

最后一条是个有用的后备手段:**如果你确实需要某一个子域用不同的加密模式,可以用 Configuration Rule 单独覆盖,不必改 zone 级设置。**

## 常见困惑速查

| 现象 | 原因 |
|---|---|
| `dig` 查出来的 IP 不是我的服务器 | 橙云开着,这是正常的 |
| 在 CF 里加了 CNAME,`dig` 却只看到 A 记录 | 同上,橙云会把真实指向藏起来 |
| 改了记录不生效 | 新记录约需几分钟收敛;改旧记录要等 TTL([05 篇](05-domain-and-dns.md)) |
| `ERR_TOO_MANY_REDIRECTS` | 多半是 Flexible 模式 + 源站强制跳 HTTPS |
| `521` | 源站拒绝了 CF 的连接(源站挂了,或防火墙没放行 CF) |
| `525` / `526` | CF 到源站的 TLS 失败——源站证书有问题,或源站根本不做 TLS([06 篇](06-https-and-certificates.md)) |
| 国内访客报 QUIC 相关错误 | 关掉 zone 的 HTTP/3 试试 |

## 一句提醒

把 DNS、CDN、证书、托管、隧道全放在一家,收益是省心,代价是**它挂了你全挂**。Cloudflare 历史上有过全球级故障。

对个人项目这个权衡完全划得来。但值得心里有数:**你的域名 NS 记录还在注册商那里**,真出事了,把 NS 改回去就能换掉整个 Cloudflare——这是你的退路,别忘了它存在([05 篇](05-domain-and-dns.md)模型三)。
