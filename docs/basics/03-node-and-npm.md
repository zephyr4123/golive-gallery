# 03 · Node 与 npm

> 教程让你敲 `npm ci`、`npm run build`,然后说"把 `dist/` 传上去"。
> 这一篇解释:Node 是什么、依赖是什么、构建把什么变成了什么、以及为什么最后上线的是 `dist/` 而不是你写的那些文件。

## JavaScript 原本只活在浏览器里

JavaScript 这门语言发明出来是给浏览器用的——让网页能响应点击、能做动画。它的运行环境就是浏览器,离开浏览器它什么也做不了。

**Node.js 把 JavaScript 从浏览器里搬了出来**,让它能像 Python、Java 一样直接在你的操作系统上跑,能读写文件、能开网络服务、能调用命令行。

所以本项目里的 JavaScript 分两种,别混:

| | 跑在哪 | 干什么 |
|---|---|---|
| 网站的 JS(`src/` 里那些) | **访客的浏览器** | 页面交互、动画 |
| 工具的 JS(Vite、TypeScript 编译器、本项目的 `golive` CLI) | **你的电脑上的 Node** | 把源码加工成能上线的文件 |

两边写的是同一门语言,但用途完全不同。**Node 只在你开发的时候用到,访客的电脑上不需要装 Node。**

这一点很关键:静态站上线之后,服务器上跑的不是 Node,只是把文件递出去而已(见 [01 篇](01-how-the-web-works.md)的静态站定义)。

```bash
node -v      # 看装没装、什么版本
```

装 Node 的时候 **npm 会跟着一起装上**,不用单独装。

## npm:替你管依赖的那个东西

写代码时你不会什么都自己造。要做动画就用现成的动画库,要做图标就用现成的图标库——这些别人写好、你直接拿来用的代码包,叫**依赖**(dependency)。

**npm**(Node Package Manager)干两件事:把依赖下载下来,以及记住你用了哪些、哪个版本。

### package.json:这个项目要什么

每个项目根目录有一个 `package.json`,是这个项目的说明书。本项目 Denta 站的真实内容:

```json
{
  "name": "denta",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "lucide-react": "^0.500.0",
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "devDependencies": {
    "vite": "^7.0.0",
    "tailwindcss": "^4.0.0",
    "typescript": "~5.6.0"
  }
}
```

三块各管一摊:

- **`dependencies`** —— 网站本身要用的。这些代码最后会被打包进访客下载的文件里
- **`devDependencies`** —— 只在你开发时用的工具。**不会进最终产物**,访客一个字节都不会下载到
- **`scripts`** —— 给命令起的短名字。`npm run build` 就等于执行 `tsc -b && vite build`,不用背长命令

版本号前面那个符号是有含义的:

| 写法 | 意思 |
|---|---|
| `^19.0.0` | 19.x.x 里最新的都行,但不要跳到 20 |
| `~5.6.0` | 只接受 5.6.x,更严格 |
| `19.0.0` | 就要这一个,一个数字都不许差 |

### package-lock.json:实际装的是哪一版

`package.json` 写的是"范围",`package-lock.json` 记的是**上次装的时候实际锁定的确切版本**,精确到每一个间接依赖。

这个区别决定了两条命令的差别:

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `npm install` | 按 `package.json` 的范围装,可能装到更新的版本,并**改写** lock 文件 | 你要新增或升级某个依赖时 |
| `npm ci` | **严格按 lock 文件装**,一个字都不差;装之前先清空 `node_modules` | 部署、CI、以及任何"我要和上次完全一样"的场合 |

本项目所有部署命令一律用 `npm ci`,原因就一条:**同样的输入必须得到同样的输出**。用 `npm install` 部署,你本机跑通的和服务器上跑出来的可能是两个东西,出了问题无从查起。

🔴 **`package-lock.json` 必须提交进版本库。** 它是可复现构建的唯一依据。

### node_modules:装下来的东西堆在这

跑完 `npm ci`,项目里会出现一个 `node_modules/` 文件夹,所有依赖的实际代码都在里面。它通常有几百 MB、几万个文件。

🔴 **`node_modules/` 绝不提交进版本库**,它被 `.gitignore` 挡在外面。理由:它完全可以由 `package.json` + `package-lock.json` 重新生成,提交它等于把一个能自动重建的东西塞进历史里永远背着。

删掉也不用怕,`npm ci` 一跑就回来了。

## 构建:把你写的变成浏览器能读的

你在 `src/` 里写的代码,浏览器**直接读不了**。原因有几层:

- 用的是 **TypeScript**(JavaScript 加了类型检查的版本),浏览器只认 JavaScript
- 用的是 **React 的 JSX 语法**(在 JS 里直接写标签),这也不是标准 JavaScript
- 代码拆在几十个文件里,浏览器一个个去下载会很慢
- 里面有大量给人看的空格、换行、长变量名,机器不需要

**构建**(build)就是把这些一次性处理掉的过程。本项目用的构建工具是 **Vite**。

```bash
npm run build
```

跑完之后出现一个 `dist/` 文件夹。这是 Denta 站构建完的真实样子:

```
dist/
├── index.html                    2996 字节
└── assets/
    ├── index-5TJ8J1MI.js       233015 字节
    └── index-wqoXrgw6.css       51668 字节
```

**三个文件,就是整个网站。** 几十个源文件、几百 MB 的 `node_modules`,最后浓缩成这三个。

注意文件名里那串 `5TJ8J1MI`——它是根据文件内容算出来的指纹。内容一变,名字就变。这样浏览器可以放心地把文件缓存很久:名字没变就说明内容没变,直接用缓存;你改了代码重新构建,文件名变了,浏览器自然会去下新的。**这就是为什么你不需要教访客"清一下缓存"。**

上线要传的就是 `dist/` 里的东西。`src/`、`node_modules/`、`package.json` 一概不用传——服务器只需要把这三个文件递出去。

⚠️ 所以 `dist/` 是**构建产物**,不是源码。它也在 `.gitignore` 里(平台会自己构建),本地删了随时能重新生成。

## dev 和 preview:两个都是"本地看一眼",但差别很大

```bash
npm run dev        # 开发服务器,默认 http://localhost:5173
npm run preview    # 预览服务器,默认 http://localhost:4173
```

| | `dev` | `preview` |
|---|---|---|
| 伺服什么 | 你的**源码**,现场加工 | `dist/` 里的**构建产物** |
| 改了代码 | 浏览器自动刷新 | 没反应,得重新 `build` |
| 速度 | 启动快,但每次请求现场处理 | 和真实线上一样 |
| 和线上的差距 | 有 | 基本没有 |

**写代码时用 `dev`,验证"上线后是什么样"时用 `preview`。**

🔴 **对公网分享一律用 `preview`,绝不用 `dev`。** 开发服务器会把你的源码、文件路径、项目结构一起暴露出去——[内网穿透档](../guide/02-tunneling/README.md)里这是一条硬规矩。本项目 Denta 站挂在公网上时,跑的就是 `npm run preview -- --port 4173 --strictPort`。

顺带解释那个 `--strictPort`:不加的话,端口被占用时 Vite 会**默默换一个端口**继续跑,而你的隧道还指着原来那个,于是得到一个"连得上但永远 502"的站。加上它,端口被占就直接报错退出——**宁可失败得响亮**。

## 环境隔离:依赖装在项目里,不装在系统里

`npm ci` 把依赖装进**项目自己的** `node_modules/`,不往系统里塞。所以同一台电脑上:

- A 项目用 React 18、B 项目用 React 19,互不干扰
- 删掉整个项目文件夹,系统干干净净,不留残渣

这是 Node 生态默认就做对的一件事。**其它语言要自己刻意做到**——比如 Python 必须用虚拟环境(venv 或 conda),否则 `pip install` 会污染整个系统,几个项目一冲突就是灾难。

这条在本项目是一条硬规矩:**任何语言的依赖都装在项目局部,不污染全局。**

## 版本

本项目验证时的实际环境:Node `v26.0.0`、npm `11.12.1`、Vite 7、React 19、TypeScript 5.6。

Node 的版本号有个规律:**偶数是长期支持版(LTS),奇数是尝鲜版**。生产项目挑偶数版。

平台构建时用哪个版本可以钉死——本项目的 Acreage 站就在仓库里钉了 Node 22 给 Cloudflare Pages 用,避免平台默认版本变动把构建搞挂。
