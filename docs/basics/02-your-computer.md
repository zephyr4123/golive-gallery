# 02 · 你的电脑

> 所有教程都从"打开终端,敲这条命令"开始,却没人解释终端是什么、命令敲进了哪里。
> 这一篇补上。看完你会知道:命令在哪执行、`localhost` 是谁、端口是什么、以及一个程序"跑着"到底是什么状态。

## 终端:用打字的方式使唤电脑

平时你用鼠标点图标,电脑替你把"点击"翻译成动作。**终端**(Terminal,也叫命令行、shell)是同一件事的另一种入口:你打字,电脑照做。

打开方式:

- **macOS** —— 聚焦搜索(⌘ + 空格)输入 `Terminal`
- **Windows** —— 开始菜单搜 `PowerShell` 或 `Windows Terminal`
- **Linux** —— 通常是 Ctrl + Alt + T

打开后你会看到一行提示符,末尾有个光标在闪。你敲一行字、按回车,它执行、打印结果、再给你一个新的提示符。

为什么部署教程一律用终端而不是图形界面?三个实在的原因:

1. **命令可以精确复制**。"点左上角第三个菜单里的第二项"会随版本变化,`npm run build` 五年后还是这行
2. **命令可以被检验**。本项目有一条硬规矩:一条规矩如果没法用一条命令查它有没有被违反,它就只是墙上的标语
3. **服务器上没有图形界面**。你租的云服务器开机就是一个终端,没有桌面可点

**敲错命令不会弄坏电脑。** 绝大多数命令要么执行成功,要么报个错什么也没发生。真正有破坏力的是少数几个(比如 `rm -rf`),教程里遇到会明确提示。

## 当前目录:命令是"在某个位置"执行的

这是新手最容易卡住、又最少被解释的一点。

终端任何时刻都**站在某个文件夹里**。你敲的命令,默认就作用于那个文件夹。所以同一条命令,站的位置不同,结果完全不同。

```bash
pwd     # print working directory:我现在站在哪
ls      # 列出当前文件夹里有什么(Windows PowerShell 用 dir 或 ls 都行)
cd 某个文件夹名   # 走进去
cd ..            # 退回上一层
```

教程里写 `cd sites/denta && npm run build`,意思就是"先走进那个文件夹,再执行构建"——因为构建命令只有站在项目文件夹里才知道要构建什么。

**报错 `no such file or directory` 时,九成不是文件丢了,是你站错了地方。** 先 `pwd` 看看自己在哪,再 `ls` 看看眼前有什么。

## 路径:文件的地址

- **绝对路径** 从根开始写全,不管你站在哪都指向同一个地方:`/Users/你的用户名/projects/golive_gallery/sites/denta`
- **相对路径** 从当前位置算起:`sites/denta` 意思是"从我现在站的地方往下找"

两个到处都会遇到的简写:

| 写法 | 意思 |
|---|---|
| `.` | 当前文件夹 |
| `..` | 上一层文件夹 |
| `~` | 你的用户主目录(macOS 上是 `/Users/你的用户名`) |

本项目文档里出现的 `~/.cpolar/cpolar.yml`,拆开就是:你的主目录 → 一个叫 `.cpolar` 的文件夹 → 里面的 `cpolar.yml` 文件。

**名字以点开头的文件和文件夹默认是隐藏的**,`ls` 看不见,要 `ls -a` 才显示。配置文件几乎都长这样,这不是什么高深设定,只是一个约定俗成的"别碍眼"标记。

## localhost:你的电脑对自己的称呼

`localhost` 是一个特殊的名字,永远指向**你这台机器自己**。它对应的 IP 是 `127.0.0.1`(IPv6 写法是 `::1`)。

访问 `http://localhost:4173` 的意思是:"我要连的服务就跑在我这台电脑上"。这个请求根本没出网卡,别人也访问不到——**你的同事在他的电脑上打开 `localhost:4173`,连的是他自己的机器,不是你的。**

这条正是[内网穿透档](../guide/02-tunneling/README.md)存在的理由:东西跑在你的 `localhost` 上,别人看不见,得想办法把它捅到公网去。

⚠️ **一个实测坑**:`localhost` 和 `127.0.0.1` 通常等价,但不总是。本项目实测,`vite preview` 只监听 IPv6 回环 `[::1]`——

```bash
curl -o /dev/null -w '%{http_code}\n' http://localhost:4173/    # 200
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4173/    # 000,连不上
```

`localhost` 会同时尝试 IPv4 和 IPv6,`127.0.0.1` 只走 IPv4。所以配隧道回源地址时**一律写 `localhost`**,写 `127.0.0.1` 会得到一个"隧道显示已连接、访客却 502"的诡异局面。

## 端口:同一台机器上的门牌号

一台电脑只有一个 IP,但上面可能同时跑着好几个服务。怎么区分?靠**端口**——一个 0 到 65535 的数字,附在地址后面用冒号隔开。

```
http://localhost:4173
                └─┬─┘
                 端口
```

几个约定俗成的:

| 端口 | 谁用 |
|---|---|
| 80 | HTTP(明文网页)。网址里不写端口时默认就是它 |
| 443 | HTTPS(加密网页)。`https://` 不写端口时默认是它 |
| 5173 / 4173 | Vite 的开发服务器 / 预览服务器默认端口 |
| 22 | SSH(远程登录服务器) |

所以 `https://denta.<你的域名>/` 其实是 `https://denta.<你的域名>:443/` 的省略写法。

**一个端口同一时刻只能被一个程序占用。** 第二个程序想用同一个端口会失败——这就是 `port already in use` 报错的全部含义。

看谁占着某个端口:

```bash
lsof -nP -iTCP:4173 -sTCP:LISTEN     # macOS / Linux
```

⚠️ 这条命令有个**实测陷阱**:如果那个程序是以 `root` 身份跑的,普通用户执行 `lsof` **看不到它**。本项目实测过一次——cpolar 的服务明明在 9200 端口提供面板(日志白纸黑字写着),`lsof -iTCP:9200` 却查不到任何东西,`curl` 一试就是 200。查不到不等于没跑,直接 `curl` 一下更可靠。

## 进程:一个程序"正在跑"

你在终端敲了一条启动命令,它开始运行并且**不还给你提示符**——这时候它就是一个正在运行的**进程**。

三种常见形态:

- **前台运行** —— 占着这个终端窗口。**关掉窗口,程序就死了**。按 `Ctrl + C` 主动停止
- **后台运行** —— 命令末尾加 `&`,或者用 `nohup ... &`,它脱离终端继续跑
- **服务 / 守护进程**(daemon)—— 注册给操作系统托管,开机自启、崩了自动重来

看有哪些进程在跑:

```bash
ps aux | grep 程序名     # 列出匹配的进程,第二列是它的 PID(进程编号)
kill <PID>              # 让某个进程退出
```

**这一段直接决定了[内网穿透档](../guide/02-tunneling/README.md)的性质。** 那一档里网站活在你机器上的一个进程里:

- 关掉终端窗口 → 进程没了 → 网站打不开
- 合上笔记本睡眠 → 网络断了 → 网站打不开
- 换个 Wi-Fi → 长连接断了 → 网站打不开

这不是配置没做好,这就是那门技术的定义。想通了这一层,那一档所有"限制"就都不再是限制。

## 环境变量:传给程序的开关

程序运行时能读到一组"当前环境的设定",叫**环境变量**。最常见的用途是把不该写死在代码里的东西(域名、密钥、服务器地址)从外面传进去。

```bash
echo $HOME              # 看某一个
env                     # 看全部
export MY_VAR=hello     # 临时设一个(只在当前终端窗口有效)
```

本项目的域名就是这么处理的:代码里只写 `BASE_DOMAIN` 这个名字,真实值从环境变量或 `.env` 文件注入。这样任何人 fork 下来配上自己的域名就能用,**不是为了保密,是为了解耦**。

🔴 **一条硬规矩:密钥、令牌、密码绝不写进代码,也绝不提交进版本库。** 它们该待在环境变量、或者被 `.gitignore` 挡住的本地文件里。这条在 [04 篇](04-git-and-github.md) 还会再提一次——因为提交进 Git 的东西,删掉也还留在历史里。
